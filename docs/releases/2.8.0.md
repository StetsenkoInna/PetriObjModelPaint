# 2.8.0

Build and edit composed Petri-object models directly through MCP, navigate in
every direction, and improve spacing without rebuilding the network.

## Direct model tools

- Structured documents now include objects, nesting, replication groups,
  templates, symbolic parameters and complete port connections.
- Ports are derived from object members. `placeFusion` shares one marking between
  a master place and local aliases; `transitionToPlace` delivers tokens from a
  transition to a place in another object. Ordinary and read arcs remain local.
- Atomic edits support ownership changes, nested replication, explicit external
  links and ungrouping. Invalid batches leave the document unchanged.
- Stable IDs, negative coordinates, template arguments, visibility and boundary
  connection offsets survive save/open. Transaction snapshots preserve symbolic
  values and IDs, while new copies receive new IDs.
- Library methods, saved templates and composed PNML fragments can be inserted
  directly. Fragment export retains internal composition and reports omitted
  external links.
- Direct camera controls and Undo/Redo complement validation, simulation and
  saving. The existing UI tools remain available.

## Canvas and spacing

- The canvas pans in every direction, including left and above the origin. A new
  canvas starts with world coordinate (0, 0) in the center. Moving the camera does
  not move model elements or change saved coordinates.
- **Improve spacing** is available in the left toolbar below the object tool and
  in **View > Improve spacing**. MCP exposes it as `optimize_model_layout`, with
  preview and Undo support.
- Spacing changes geometry while preserving IDs, connections, markings, timing,
  parameters, object ownership, nesting, groups and shared-place semantics. It
  considers rendered labels, weights, object headers and port labels, and expands
  frames where needed.
- Results report remaining label overlaps and arrow crossings with element IDs.
  Existing straight arrows are retained. A result is verified only when all
  checks in its stated verification scope pass; unresolved crossings are not
  presented as fully resolved.

## Updates

The updater keeps the behavior introduced in 2.7.0: one check when the application
opens, installation from GitHub, remind tomorrow, skip this build and optional
startup checks. No periodic polling was added. An installed 2.7.0 can offer this
release through its existing update dialog.

See [Desktop MCP](../desktop-mcp.md) for the direct tool contract and
[Desktop updates](../desktop-updates.md) for installation behavior.
