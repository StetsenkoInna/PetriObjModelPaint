# 2.8.1

A patch release: no repeated names on the canvas, the application version in the
window titles, one-shot line tools in the Statistic monitor, simulation evidence in
training exports, and a canvas centering fix.

## Names on the canvas

- Places, transitions and Petri-objects share one set of names, and nothing added to
  the canvas repeats a name already there. Paste, **Duplicate Petri-object** and
  `Ctrl+D`, **Replicate into a group...**, saved Petri-objects stamped from the
  toolbar, **Petri-object from net library...** and nets loaded from the Nets window
  rename what they add, never what was there. Elements continue an `_N` count
  (`P1_2`, `T1_2`), objects keep the spaced style (`Generator 2`).
- A shared place is one place with one name. Joining two places gives the joined half
  the master's name (`Ctrl+Z` restores its own), renaming either half renames the
  whole set, and a copied pair gets a new name of its own that nothing outside the
  pair may use.
- New places and transitions drawn with their tools take the first free `P<n>` or
  `T<n>` on the canvas, so a net opened from a file no longer gets a second `P1`.
- The MCP tools `edit_model` (`put_*`, `replicate_object`), `insert_model_template` and
  `insert_model_fragment` follow the same rule. Opening or importing a file,
  `apply_model` and `open_model` keep every name as saved.

## Version

- The running version is shown in the editor's title bar, on the Welcome window next
  to the product name, and in the new **Help > About PetriObjModelPaint...**, which
  also lists the Java runtime and operating system for bug reports.
- The update notice states the installed version, or that the offer is a new build of
  the version already installed. The desktop MCP server reports the application
  version in `serverInfo`.

## Statistic monitor

- The vertical and horizontal line tools now place one line per activation. After
  a click the tool switches itself off and its toolbar button is released, so later
  clicks no longer add a second, third or fourth line. Press the button again to
  place another one.

## Training export

- **AI > Export training data** runs the same automatic simulation attempts as a
  review export (horizons 100, 1000 and 10000, on the exact exported PNML) and records
  them in `verification.json` under `simulation`. Observed execution is evidence only:
  the status stays `unknown`. A review export keeps its runs in the review record, so
  nothing runs twice. A model without places gets no attempts and a missing-data note.
- The export dialog no longer offers the main-window screenshot checkbox. The overview
  and every object image, with parameter tables, are always included. The MCP tool
  `export_training_data` still accepts `include_screenshot` for agents.

## Canvas

- A new canvas is centered correctly on every platform, and the Swing tests that
  depend on it are stable on macOS.
- Duplicating the same Petri-object again puts the new copy on the next free spot to
  the right instead of exactly on top of the previous copy.

## Libraries

`petri-api` is released as 2.8.1 because `ChartConfigDto` gained `releaseLineTools()`,
and `petri-model` as 2.8.1 for `CanvasNames`, the canvas naming rule. `petri-math` and
`petri-server` keep their current versions.

See [Training bundles, reviews and image export](../training-data-export.md) for the
bundle contents.
